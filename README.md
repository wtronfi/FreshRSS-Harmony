# FreshRSS for HarmonyOS

一个面向 HarmonyOS 的原生 FreshRSS 阅读客户端。

项目使用 FreshRSS 提供的 **Google Reader Compatible API** 与服务器通信，主要用于在 HarmonyOS 手机上获得更轻量、原生的 RSS 阅读体验。

本项目在部分 UI、文章列表以及阅读器交互设计上参考了开源项目 [Capy Reader](https://github.com/jocmp/capyreader)，并针对 HarmonyOS 与 FreshRSS 的使用场景进行了独立实现和适配。

> 当前项目以个人使用和稳定性为优先目标，暂未上架 AppGallery，可通过 GitHub Releases 下载HAP安装包自行侧载安装。

## 安装

前往 GitHub 的 **Releases** 页面下载最新版本的签名 HAP 安装包。

通常文件名类似：

```text
entry-default-signed.hap
```

然后通过 HarmonyOS 设备支持的侧载方式安装。

---

## 升级与签名说明

如果设备上已经安装过旧版本，后续升级必须继续使用相同的应用签名身份。

如果安装时出现：

```text
install sign info inconsistent
```

通常表示当前设备上的旧版本与新版本 HAP 使用了不同的签名。

这种情况下可以先卸载旧版本再重新安装。

例如通过 HDC：

```bash
hdc shell bm uninstall -n com.freshrss.reader
```

需要注意：

> 卸载应用会同时清除本地设置、登录状态和缓存数据。

因此正式长期使用后，建议始终保持同一套签名证书进行后续版本构建。

## FreshRSS 服务器要求

使用本客户端前，需要有一个已经正常部署并可访问的 FreshRSS 服务。

本项目通过 FreshRSS 的 **Google Reader Compatible API** 与服务器通信，因此 FreshRSS 服务端需要启用相应的 API 功能。

登录时服务器地址只需要填写 FreshRSS 根地址。

例如：

```text
https://rss.example.com
```

无需填写：

```text
/api/greader.php
```

客户端会自动处理对应的 API 路径。

## 刷新机制

为了减少服务器请求并提升移动端使用体验，目前提供三种主要刷新方式。

### 仅手动

有本地首页缓存时：

* 启动 App 不自动刷新
* 返回首页不请求未读接口
* 只有手动点击刷新按钮才访问 FreshRSS
* 阅读产生的未读变化通过本地状态即时更新

适合希望尽量减少服务器请求的用户。

### 启动时刷新

* App 首次进入首页时进行一次完整刷新
* 从文章列表或设置页返回首页时不再次完整刷新

### 进入 / 返回首页时仅刷新未读数量

已有本地缓存时：

* 只请求 FreshRSS 的未读统计
* 不重新获取完整订阅列表
* 不重新进行完整首页同步

同时加入了请求节流，避免短时间内反复进入首页产生重复请求。

## 连续阅读

FreshRSS 的文章接口通常采用分页方式返回数据。

客户端会保存分页 continuation 信息，在当前页文章阅读完之后继续向 FreshRSS 请求下一页。

因此即使第一页只有 50 篇文章，也可以继续阅读：

```text
第 51 篇
第 52 篇
第 53 篇
……
```

而不会在第一页结束后中断。

这也是当前项目重点保持稳定的功能之一。

---

## 离线使用

客户端会优先使用本地缓存改善离线体验。

### 首页

无网络时：

* 使用已经缓存的订阅与未读信息
* 不必先等待网络请求超时

### 文章列表

如果相应列表已经缓存：

* 可以离线打开
* 可以查看已缓存文章
* 滚动到底部时不会继续发起网络分页请求

恢复网络后，可根据当前刷新策略重新与 FreshRSS 同步。

---

## 网络错误提示

针对常见网络问题，客户端会尽量显示更容易理解的提示，包括：

* 请求超时
* 无法解析服务器域名
* 无法连接 FreshRSS
* HTTPS / TLS 连接错误
* FreshRSS 服务器暂时不可用
* FreshRSS 返回的数据异常

对于认证失效等情况，会继续按照账户登录逻辑进行处理。

## 隐私说明

本应用不提供中转服务器。

FreshRSS 账户与 RSS 数据由客户端直接与用户自行配置的 FreshRSS 服务器通信。

建议不要在 GitHub Issues、截图、日志或其他公开位置泄露以下信息：

* FreshRSS 用户名
* 登录密码
* API Auth 信息
* 私有服务器地址
* 私有域名
* Cookie
* Authorization Header
* HTTPS 私有证书信息
* 应用签名证书及密码

## 当前项目定位

这个项目目前主要面向个人使用，因此开发优先级为：

1. Bug 修复
2. 稳定性
3. 性能
4. FreshRSS API 兼容
5. HarmonyOS SDK 兼容
6. 小型 UI 优化

当前暂不计划重点开发：

* 全文搜索
* Tag 标签体系
* RSS 自动发现
* AppGallery 发布
* 复杂页面切换动画

整体方向是：

> 稳定、轻量、自用体验优先。
